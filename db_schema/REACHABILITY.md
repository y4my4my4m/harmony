# Reachability

Generated by `scripts/generate-reachability.sh`. Do not edit by hand.
`scripts/generate-reachability.sh --check` rewrites it and exits non-zero when the
committed copy was stale.

How execution enters every function in a schema built from `db_schema/init/`.
`SURFACE.tsv` lists what exists and what may execute it; this lists what reaches it.

## What the graph shows

The public schema holds 363 functions. 313 are entered from somewhere: 155 are named by application code, 128 of those as a literal inside `rpc()`. 148 are reached only by a trigger firing, 9 only by an RLS policy evaluating, and 35 are never referenced outside the database at all and run only because another reachable function calls them.

50 functions have no entry point at all: no RPC call in this repository, no trigger, no policy, no view, no default, no check, no index, no cron job, and no caller among the other 362. What that costs depends on who may still EXECUTE them - 3 answer `anon`, 0 answer any signed-in session, 47 answer only a caller holding the service key, and 0 cannot be called at all.

All 136 functions returning `trigger` carry at least one trigger. One with none would be uncallable by construction: PostgREST does not route to a function returning `trigger`, and `SELECT` of one raises 0A000. That is the only way a function here can be dead beyond argument.

PostgREST publishes every function in `public`, and Supabase grants EXECUTE on a new one to `anon` and `authenticated`. `init/98_enable_rls.sql` takes that back for 55 functions; the other 308 are endpoints whether or not anyone intended them. `anon` may EXECUTE 172 of the 227 functions that do not return `trigger`.

Reachable does not mean safe and unreferenced does not mean droppable. Caller matching against application code is deliberately over-inclusive, because a false "dead" removes a live endpoint while a false "live" costs a line here. Call edges are matched out of `prosrc` by name, so a function invoked through a name assembled at run time inside `EXECUTE` is found only if that name appears whole in the body. Nothing here reads a running instance either: a drifted one holds functions `init/` does not define, and this graph says nothing about those.

## Reachable only as an anonymous HTTP endpoint

## Dead

No entry point and no role that can call one. A function returning `trigger` with no trigger is the only way to land here while any grant remains, because PostgREST does not route to one and `SELECT` of one raises 0A000.

None. Every function in a fresh build can be invoked by someone.
